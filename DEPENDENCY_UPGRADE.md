# Dependency audit and Expo 57 migration

Audited on 2026-09-07. The repository now targets Expo 57.0.20, React Native
0.86.3, and React 19.2.3. Native module versions follow Expo's compatibility
matrix, rather than independently selecting the latest React Native release.

## Setup and repeatable checks

Use Node 22 LTS (at least 22.13) and the pinned Yarn 4.18.0:

```sh
nvm use
corepack enable
yarn install --immutable
yarn typecheck
yarn test
yarn doctor
yarn expo export --platform all
yarn npm audit --all --recursive
```

Copy `.env.example` to `.env` and supply development RPC credentials before
running the app. The export validation used `EXPO_NO_DOTENV=1`, so it did not
embed local credentials or contact a blockchain. Build outputs were kept outside
the repository. Yarn's generated installation state is no longer tracked.

## Changes

- Updated direct and transitive dependencies and regenerated the Yarn lockfile.
  Removed unused direct navigation/tooling dependencies and the unavailable
  Redux DevTools script. Declared Buffer and stream polyfills directly.
- Added an entry point that loads crypto globals before Router evaluates wallet
  modules. Removed the layout-time Buffer and fake global location assignments.
- Migrated React Navigation imports to `expo-router/react-navigation` and null
  header renderers to functions. Expo Router 56+ owns its navigation integration.
- Upgraded Reanimated 3 to 4 with its matching Worklets package, and bottom-sheet
  4 to 5. Disabled automatic sheet sizing to preserve existing snap-point indices.
- Replaced React Native's removed SafeAreaView with safe-area-context, migrated
  splash configuration to its plugin, and removed obsolete assetBundlePatterns.
- Selected the Expo SVG transformer. Scoped Metro compatibility handling to
  rpc-websockets' browser export and noble's crypto browser mappings.
- Migrated crypto-es 3 to named exports. Added a fixed ciphertext generated by
  the old crypto-es 2 installation to verify existing encrypted data still
  decrypts, plus randomized Unicode round-trip coverage.
- Added styled-components native theme declarations, gradient tuple types, and
  typed thunk dispatch. Fixed an existing unclosed TopBar JSX element.
- Merged onto the SDK 52 line already on `main`: kept its `expo run:*` scripts,
  app identifiers, Android permissions, dev-launcher plugin, committed native
  project folders, and the `native-modules/didcomm` sources, and added
  `expo-dev-client` at the SDK 57 version. Dropped `newArchEnabled` from app.json
  because the SDK 57 config schema rejects it (the New Architecture is always on).
- Kept the project's previous non-strict TypeScript behavior explicitly because
  TypeScript 6 changes defaults. Added explicit React, native, Node, and Jest types.
- Retained Babel 7 and Jest 29 to match Expo's integrations. TypeScript 6.0.3
  follows Expo's recommendation; Babel 8, Jest 30, and TypeScript 7 are not suitable
  drop-in upgrades for this stack.

## Audit results and remaining advisories

The original Yarn Classic audit reported 2 critical, 46 high, 29 moderate, and
9 low findings. The final Yarn 4 recursive audit reports **zero critical/high**
security advisories and the four advisories below. These tools count findings
differently, so the original and final totals are not a one-to-one comparison.

The scoped `@ethersproject/providers/ws` resolution updates its exact ws 8.18.0
pin to 8.21.3, fixing the ws memory-disclosure and memory-exhaustion advisories
without changing its major version. Remove this resolution when the parent
package updates its pin.

| Package | Severity | Dependency path / remaining work |
| --- | --- | --- |
| decode-uri-component 0.2.2 | Moderate | Expo Router → query-string 7.1.3. [GHSA-vcc3-ghjq-m6fr](https://github.com/advisories/GHSA-vcc3-ghjq-m6fr). The fix is 0.5.0, which changes to ESM while query-string 7 requires CommonJS. Needs an upstream Router/query-string migration or a separately validated patch; no incompatible forced resolution was added. |
| elliptic 6.6.1 | Low | Alchemy SDK → ethers 5 signing-key. [GHSA-848j-6mx2-7j84](https://github.com/advisories/GHSA-848j-6mx2-7j84). The latest elliptic remains flagged. App transaction signing uses the separate ethers 6 dependency, but this does not remove the vulnerable transitive package. |
| stream-json 1.9.1 | Moderate | Solana web3.js → jayson. [GHSA-528h-pc64-c93x](https://github.com/advisories/GHSA-528h-pc64-c93x). A newer major contains the fix; jayson imports the old streamers and verifier paths. No incompatible major override was applied. |
| uuid 7.0.3 / 8.3.2 | Moderate | jayson and Xcode tooling. [GHSA-w5hq-g745-h8pq](https://github.com/advisories/GHSA-w5hq-g745-h8pq). Fixed in 11.1.1; parents still require older majors. Their inspected call sites use v4, while the advisory concerns buffer handling in v3/v5/v6. Still reported rather than suppressed. |

Yarn also reports seven upstream package deprecations (abab, domexception, glob,
inflight, text-encoding, whatwg-encoding, yaeti). Those are separate from the four
security advisories. Upstream peer metadata warnings remain in Expo/Jest/Moti/
Solana packages; the app's direct peer requirements and Expo Doctor checks pass.
The audit is not clean, and this dependency audit is not a full wallet security review.

## Validation and limits

- Immutable dependency installation passed.
- TypeScript check passed.
- 25 tests across 5 suites passed, including legacy ciphertext compatibility.
- Expo Doctor: 20/21 checks passed. The remaining check warns that the committed
  `ios/` and `android/` projects will not pick up app.json changes unless
  prebuild runs; see below.
- Expo native configuration/plugin introspection passed.
- Production exports passed for web, iOS, and Android (native Hermes bytecode).

Native Xcode/Gradle compilation and simulator/device interaction were not run.
The committed `ios/` and `android/` projects and `ios/Podfile.lock` still reflect
the SDK 52 / React Native 0.76 prebuild, so run `npx expo prebuild --clean`
before building. The `native-modules/didcomm` sources are not referenced by
either native project, so the home screen's `Didcomm.helloWorld()` call currently
rejects with its linking error, which is caught and logged.
Create a fresh native development build for this SDK, then verify wallet import
and unlock with existing data, biometrics, camera permissions and QR scanning,
bottom-sheet gestures/snap positions, safe areas, and transaction confirmation
on development networks. Bundle checks do not establish those runtime behaviors.
